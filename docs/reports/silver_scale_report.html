Câu 1

Từ file raw đến dữ liệu chuẩn hoá

Mỗi filing ở Bronze là một file full-submission.txt nguyên bản của SEC (header SGML + nhiều khối <DOCUMENT>: HTML, XBRL, ảnh, exhibit). Bronze không bao giờ bị sửa; Silver được dựng lại từ đó qua 12 stage, mỗi stage đọc bảng Silver cha chứ không quét lại raw.

SEC EDGAR→Bronze: full-submission.txt + filing_manifest.jsonl (sha256, size)→Silver: 19 bảng Iceberg

Filing & tài liệu

filings1 row / filing, khoá accession, checksum từ manifest
documents1 row / khối <DOCUMENT>, verify hash
filing_entities1 row / vai trò (FILER, ISSUER…)

Văn bản

narrativesections (PART → ITEM) + content_blocks
tablesdocument_tables + lưới cell
links · exhibitsmọi <a href>, Exhibit Index

XBRL (số liệu tài chính)

xbrl_coreinstance, context, unit
xbrl_factsconcept + fact (Arelle nạp DTS)
enrichment · linkbasesdimension, footnote, label, network, relationship

Kiểm định

integrity266 check: khoá, 32 FK, lineage, group 1..N, count khai báo, cây section, lưới cell, so lại với Bronze trên filing mẫu

Ví dụ thật: Apple 10-K năm tài chính 2024 (0000320193-24-000123)

Một file raw 9,76 MB được tách thành ~14.400 row có khoá, quan hệ cha–con và lineage về đúng byte offset trong file gốc.

Câu 2

Lỗi gặp phải: lưu lại, tóm tắt, trực quan

Lỗi được lưu ở 3 nơi: log JSON có cấu trúc của từng run (logs/*.jsonl, mỗi lỗi có event, filing, stage), report integrity PASS/WARN/FAIL kèm tối đa 5 sample ID, và tài liệu AGENTS.md ghi lại nguyên nhân + cách xử lý. Có hai loại: lỗi dữ liệu (SEC/filer làm khác chuẩn) và lỗi hạ tầng (RAM, đĩa, mạng, điện).

Sự kiện lỗi khi build 500 công ty

Số event mức error trong log build (21–26/10), theo loại; 15 lần pipeline dừng rồi chạy lại

Số cảnh báo tăng theo dữ liệu, tỉ lệ thì ổn định

Row bị cảnh báo / 1 triệu row được kiểm. Loại cảnh báo mới (section lặp, document chỉ có root) chỉ xuất hiện từ 50 và 200 công ty

Câu 4

Tối ưu đã làm: đo trước, sửa đúng chỗ, đo lại

Bài toán doanh nghiệp: giảm thời gian và tài nguyên mà không đổi một row dữ liệu. Cách làm: profile từng stage (thời gian, CPU/wall, RAM), xác định ~95% thời gian XBRL là Arelle nạp lại cùng một DTS 3 lần, stage filings đọc lại 226 GB chỉ để tính hash đã có, integrity dùng SQLite + index trên 269 triệu row. Benchmark A/B trên cùng mẫu 2% (769 filing): cả hai bản ghi đúng 4.716.499 row, integrity cùng kết quả.
