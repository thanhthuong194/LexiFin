# Gold: native RAG chunks (`native_rag.chunks`)

One Iceberg table of retrieval chunks built from the Silver narrative by `scripts/native_rag/build_chunks.py`. Source of truth is the code: schema and row checks in `contracts/native_rag/chunks.py`, table spec in `storage/native_rag/chunks.py`, chunking rules in `transforms/native_rag/`, batching and metadata in `pipelines/native_rag/`, audit in `quality/native_rag/audit.py`. Design and decisions: `docs/plans/native_rag_chunking_draft.md`.

Numbers are from `data/` (343 filings, 523 narrative documents), chunks rules v6, 2026-11-17.

## 1. Storage

- Own catalog: `<gold_dir>/_catalog/gold.db` (PyIceberg `SqlCatalog`, SQLite), files under `<gold_dir>/gold/native_rag/chunks/`. `gold_dir` defaults to the Silver `--data-dir`. Purging Gold never touches the Silver catalog.
- Partition `year(filing_date)`. Grain: one chunk of one narrative document (primary HTML or EX-99 exhibit). Key `chunk_id` = `{document_id}:chunk:{NNNNNN}`.
- Table properties pin what rows were built with; a run whose values differ writes nothing (`rejected`): `lexifin.rules-version`, `lexifin.tokenizer` (`Qwen/Qwen3-Embedding-0.6B@<revision>`), `lexifin.chunk-params` (all tunables), `lexifin.silver-rules` (rules versions of every Silver table read: filings, documents, filing_entities, sections, content_blocks, document_tables, document_table_cells, exhibits, xbrl_instances, xbrl_contexts, xbrl_concepts, xbrl_facts). Change any of them: purge `native_rag.chunks` with `open_gold_catalog`, then build.

## 2. Columns

| Use | Columns |
|---|---|
| Keys, links | `chunk_id`, `filing_id`, `document_id`, `section_id`, `table_id` (table chunks), `block_ids` (Silver blocks whose text the chunk holds, in order) |
| Filter | `cik`, `tickers`, `form`, `fiscal_year`, `fiscal_period` (FY/Q1–Q3; null for 8-K), `period_end_date`, `filing_date`, `section_topic`, `document_type`, `chunk_kind` (text/table) |
| Citation | `company_name`, `accession_number`, `sec_url`, `section_title`, `subheading`, `table_title` |
| Context expansion | `chunk_ordinal` (document order), `document_chunk_count`, `part`/`part_count` (pieces of one paragraph or one table) |
| Content | `context` (prefix), `text` (body) |
| Control | `token_count`, `chunk_sha256`, `processed_at` |

- Embedded string = `context + "\n\n" + text`; `token_count` counts it with the Qwen3-Embedding tokenizer including `<|endoftext|>`; `chunk_sha256` hashes it. Cap 512 tokens.
- `context`: `Company | form | period | section path › subheading[ | Table: title (part i/n)]`. Period: `FY2025 (period ended …)`, `FY2025 Q2 (…)`, 8-K `filed … (event …)`.
- `company_name`: dei `EntityRegistrantName` of non-dimensional contexts (a multi-registrant filing names each subsidiary under `LegalEntityAxis`), one spelling per CIK when names differ only in case/punctuation/suffix: the earliest filing's, so new filings never change it; fallback the filer's conformed name. `tickers`: dei `TradingSymbol` of contexts whose `Security12bTitle` is not debt, `^[A-Z][A-Z.\-]{0,9}$`. `period_end_date`, fiscal fields: dei of non-dimensional contexts, fallback `report_date`.
- `section_topic`: `cover`, `business`, `risk_factors`, `cybersecurity`, `properties`, `legal_proceedings`, `market_equity`, `mdna`, `market_risk`, `financial_statements`, `controls`, `governance`, `exhibits`, `signatures`, `8k_event`, `ex99`, `other`; 10-Q items keyed by parent PART. Known mislabel: financial pages filed under 10-K ITEM 15 are `exhibits`.
- `section_title`: last element of the path; primary-document root = `Cover page`, prose kept from a TOC section = `Front matter`, EX-99 root = `EX-99.1: {Exhibit Index description}` cut to 80 chars.

## 3. Chunking rules

Structure-aware, deterministic, no LLM. Per document: drop noise → read tables → per run of blocks of one section: text between tables in topic units, each data table its own chunk.

- Noise (counted in `dropped_blocks`): in a TOC section only TOC-shaped lines ≤150 chars (PART/ITEM start, page-number end, `Table of Contents`), so prose and statements Silver left there stay; its tables are classified like any other; the block opening a detected section when it is at most min(title, 200) + 40 chars (the title goes to the path; an 8-K item laid out as one table stays); empty; no letters/digits; page numbers (`12`, `Page 3`, `xii`, `F-12`, `23.`); running headers (≤100 chars, not a sentence, not a lone footnote marker, same text with digits as `#` ≥4 times in ≥3 sections or ≥8 times, and either `Table of Contents`, a rising page counter, or at least half its occurrences within 3 blocks of a page break with only noise between: repeated segment headings and row labels stay); TOC tables (no `$`, most of ≥3 rows or both of 2 rows are PART/ITEM, a 20+ char label and a page number, SIGNATURES/EXHIBIT and a page number, or a bare `EXHIBIT 4.2`: 8-K contents tables) and signature tables anywhere.
- Tables: TOC/signature → dropped; ≤2 non-empty columns or no numeric cell → paragraphs (one per row); data table with block text <100 chars → one inline paragraph; otherwise rendered from cells as `label | value | value` with an inferred header (years/dates are labels; a lower header row of several cells splits the columns above it, e.g. `Common Stock` over `Shares | Amount` (a row with label text counts only when an upper cell spans two of its cells, no upper row has label text and the label is no exhibit number: else it is data); label-column header text such as `(In millions)` leads the header line), `$`/`%`/`)` glued to numbers (lowercase `x`/`bps` only right after a value; uppercase `X` is a check mark), units rows as notes; title = last short paragraph or a lead-in ending in `:` plus up to 3 title-like lines above; subheading = the title line closest to the table, never a company-name line (`NVIDIA CORPORATION AND SUBSIDIARIES`); a lone footnote marker (`(a)`, `*`) joins the next line; up to 5 following footnotes, then short lines that close the table (statement footers such as "See accompanying Notes…" and short notes; together under 64 tokens, not title-like or lead-ins, followed by a table, a heading, a `:` lead-in or the section end; right before a table only a statement footer, since another line introduces that table; rules v5); split by rows with the header repeated (a row over the cap is cut by tokens; parts are checked against their real `(part i/n)` prefix). Known weakness: a very wide table (15 columns, ~400-token header) gives one row per part, mostly header.
- Word-fragmented documents (over 300 text blocks, more than half ≤15 chars: absolutely positioned layouts, 55 on 500-company Silver) have consecutive text blocks joined into paragraphs ending at `.`/`!`/`?`/`:`, without subheadings.
- Text: a title-like line (≤120 chars, ≤12 words, no final `.,;:` except a company suffix) opens a unit; unit ≤ cap → one chunk; longer → fewest balanced parts between paragraphs; a paragraph over the cap → balanced parts of sentences (a sentence over a third of the budget cut by tokens), each repeating the previous part's last piece when it is at most a quarter of the budget (rules version 2: v1 let 5 documents of the 500-company Silver reach 513–514 tokens); a title-only unit joins the next unit under that unit's subheading (title lines above a sentence-split paragraph open its first part); other units <64 tokens merge into the next unit, else the previous, when it fits; never across sections or tables. Lone footnote markers are never title-like.

## 4. Operation

- Incremental by document: complete documents (ordinals 1..N = declared count) are skipped; documents with no chunks (image-only exhibits) are re-examined each run; an incomplete stored document rejects the run. Batches by filing date of at most 200 documents or 300k cells, one verified commit each. A document whose chunks fail (contract, cap) is skipped and logged; the run ends `partial` (exit 1) and retries it next time. A layout table's rows may continue in the next text chunk, but a layout table of notes after a table is never split between chunks (v7; 500-company v6 had such splits), and a lone marker (`(ii)`) never takes the first row of a layout table (v8); every other block is in exactly one chunk or a split chain.
- Audit (`--check-only`, or after every build): definition and properties, contract on every row, keys, ordinals, token cap, hashes, FKs (document, section, each block in Silver and in the chunk's section), each block in one table, one split chain or one chunk, chunk bodies under 20 chars, documents without chunks and >30% of characters outside chunks (WARN), exact rebuild of the newest 10-K/10-Q/8-K plus 5 documents by hash with full coverage (every block in a chunk or dropped, not both). Reads one filing year at a time.
- `data/` (2026-11-17, v6): build ~85 s, 25,928 chunks; audit 0 FAIL (WARN `small_chunks`); v7 and v8 give the same chunks on `data/`.
- 500 companies (homepc, 2026-11-19, v6): 3 h 23 min, 3,737,699 chunks of 65,999 documents, peak RSS 3.6 GB; audit FAIL `block_in_one_chunk` (fixed in v7). v7 (2026-11-20): 3 h 13 min, 3,737,715 chunks; audit FAIL `block_in_one_chunk` on 2 blocks (fixed in v8).

## 5. `native_rag.embeddings`

One vector per (model, chunk), built by `scripts/native_rag/build_embeddings.py` through `src/llm` (`get_embedder(<profile>)`, profiles in `config/llm_profiles.toml`; default profile Qwen3-Embedding-0.6B; builds use vLLM on Kaggle, 2× T4 behind a load balancer, at `EMBEDDING_DEFAULT_BASE_URL`, no `served_model`). Code: contract `contracts/native_rag/embeddings.py`, spec `storage/native_rag/embeddings.py`, pipeline and audit `src/rag_engine/embedding/`.

- Same Gold catalog as chunks, partition `year(filing_date)`. Key `embedding_id` = `{model_id}|{chunk_id}`; columns `chunk_id`, `document_id`, `filing_date`, `model_id`, `chunk_sha256` (hash of the embedded text the vector was made from), `dimensions`, `vector` (float32, L2-normalized: cosine = dot product), `processed_at`. Several models can share the table.
- Embedded string = the chunk's `context + "\n\n" + text` (the string the chunker counted); documents get no instruction, queries get the profile's `query_instruction`.
- Incremental: chunks whose (`chunk_id`, `chunk_sha256`) already has a vector of the model are skipped; vectors are written in verified commits of 4,096 rows, and vectors made before a failed request are committed, so a closed tunnel only stops the run: it ends with status `interrupted` (exit 1, vectors made so far committed, rows never appended twice); put the new URL in `.env` and run again. Vectors whose chunk is gone or changed (chunks rebuilt, years of either table checked) or of another size reject the run before any request: purge `native_rag.embeddings` and embed again.
- `--concurrency N` request groups in flight (`--batch-size` chunks each; the server batches them); `--limit N` for trial runs.
- Audit (after every run, or `--check-only`; one pass over each year's vectors): definition, unique keys, one vector size and every vector that long, norms within 1e-3 (NaN fails), every vector's chunk current (FAIL), chunks without a vector (WARN), `--reembed-sample` current chunks re-embedded with cosine >= 0.999 (WARN when the server is down). Between sessions of a long run, `--skip-audit` saves the full vector read.
- `data/`: re-run pending for v6 chunks (Colab T4 gave 19.6 chunks/s, GPU-bound).

## 6. Qdrant (`scripts/native_rag/load_qdrant.py`)

Serving index rebuilt from Gold at any time (`native_rag.chunks` + `native_rag.embeddings`); code in `src/rag_engine/indexing/`.

- One collection per (corpus, chunks rules version, index version, model): `sec_filings__chunks_v8__index_v1__qwen_qwen3_embedding_0_6b`; `INDEX_VERSION` (in `qdrant_store.py`) covers only the BM25 vector: bump it when BM25 changes (payload changes are caught by `point_sha256`). Later corpora (`vn_filings`, `us_law`, `vn_law`) get their own. The application reads the corpus alias (`sec_filings`), switched only after a load whose audit has no FAIL and whose HNSW is built (`--check-only` never switches it).
- Point ID = UUID5 of `chunk_id`. Vectors: `dense` (1024, cosine) and `bm25` (sparse: BM25 term-frequency weights of `context + "\n\n" + text`, lowercase words and numbers, English stopwords dropped, CRC32 term IDs, average length 116 terms measured on local Gold; Qdrant applies IDF). Hybrid queries fuse both with RRF; the query side uses `sparse.query_vector`.
- Payload: `chunk_id`, `filing_id`, `document_id`, `section_id`, `cik`, `tickers`, `company_name`, `form`, `document_type`, `fiscal_year`, `fiscal_period`, `filing_date`, `period_end_date` (RFC 3339), `section_topic`, `section_title`, `subheading`, `chunk_kind`, `table_title`, `chunk_ordinal`, `part`, `part_count`, `accession_number`, `sec_url`, `context`, `text`, `token_count`, `chunk_sha256`, `point_sha256` (digest of the payload with the text standing as `chunk_sha256`), `corpus`, `jurisdiction`, `language`. Indexes: `cik` keyword with `is_tenant`; keyword `tickers`, `form`, `document_type`, `section_topic`, `chunk_kind`, `fiscal_period`, `filing_id`, `document_id`, `section_id`, `corpus`; integer `fiscal_year`, `chunk_ordinal`; datetime `filing_date`, `period_end_date`.
- Parameters: HNSW m 16, ef_construct 200, search `hnsw_ef` 128. `--large` (500 companies): int8 scalar quantization (quantile 0.99, in RAM) with rescoring and oversampling 2.0, original vectors, sparse index and payload on disk (part of the layout check). A new collection is filled with indexing off, then `indexing_threshold` 20000. An existing collection must have exactly the requested layout, else the run stops (delete it and load again). Over 500,000 chunks the load refuses to run without `--large`.
- Incremental, one filing year at a time and inside it one chunk data file at a time (Gold files are commit batches spanning many months, so month filters would reread a year 12 times): points are compared by `point_sha256` without reading vectors, so payload-only changes re-upsert too; only new or changed points have their vectors read (Arrow float32; files located per year by `vector_index`, chunk_id → embeddings file, since PyIceberg stops pruning `In` filters over 200 values) and are upserted (512 per acknowledged request; `indexing/retry.py` retries 5xx, 429 (honouring Retry-After) and transport/socket errors with backoff, not other 4xx or unparsable replies); points no current Gold chunk backs, or of years Gold no longer has, are deleted. Chunks without a current vector leave the run `incomplete` (exit 1; embed, then load again).
- Indexing wait: `--index-timeout` (default 3600 s, 14400 with `--large`).
- Audit (after the index build, or `--check-only`; 9 checks): `collection`, `point_count` = Gold chunks with a current vector, `point_digests`, `companies`, `payload_indexes`, `sample_points` equal Gold (payload, dense cosine >= 0.999, BM25 indices and weights), `self_retrieval` (a chunk with identical text counts), `hybrid_filtered` (filtered by `cik`: the chunk and only that company), `ann_recall`: HNSW vs exact top-10 recall (mean >= 0.95, each >= 0.7; SKIP before HNSW covers 90% of vectors or on embedded Qdrant). Tests use embedded Qdrant (`QdrantClient(":memory:")`); runs use the server (`--qdrant-url`, default `http://localhost:6333`) or `--qdrant-path`.
- `data/`: re-run pending for v6 chunks.
- Company directory: `<collection>__companies`, one vectorless point per `cik`, rewritten on every load from the points actually loaded (a `cik` facet gives companies and `chunk_count`; each company's newest point gives `company_name`, `tickers`, `latest_filing_date`; Gold adds every name it filed under), so chunks still waiting for a vector are never listed; it sits next to its collection, so the alias switch moves both. Audit `companies`: the directory equals one recomputed from the points.

## 7. Retrieval (`src/rag_engine/retrieval/`, `scripts/rag/search.py`)

Question -> cited passages, reading only Qdrant and the model servers (Gold is for rebuilds).

1. One structured call to `[chat.query]` (`query.py`): question language; per corpus language, the question written in that language whatever language it was asked in, as one complete standalone question with official company names instead of tickers (not keywords: the reranker judges passages against it; the schema has one required field per corpus language, `analysis_model`, since gpt-oss otherwise copied 77/81 Vietnamese questions untranslated); a text missing or still in the question's language (Vietnamese letters for `en`, or the question copied) is dropped and translated by one short second call, else the question is searched and the plan notes it; corpora; companies (official name + ticker); years and periods (relative years resolved from today) with `period_basis` `fiscal` (FY / fiscal said) or `calendar` (a plain year); forms only when asked; up to 3 likely section topics; `wants_latest`; `filed_months` (`YYYY-MM`, a filing month the user names: "April 2022 8-K", "July 2026 earnings release", "announced on May 2, 2024"). `checked_plan` completes the model's periods from the question's words (the rules share them): half year / six months -> Q2, nine months -> Q3 (merged with other asked periods); a date (or a partial period ending on one) -> the nearest calendar quarter end, calendar basis; "(fiscal) year ended <date>" -> FY; values like `Q2 2024`, `FY2027`, `2Q24` split into period + year; relative spans ("last six months") and yearless dates give no period; a filing month in an 8-K-only question replaces years. Unknown values are dropped, not fatal. No model or a failed reply -> rules (`rule_plan`: language, years incl. `FY25`, quarters, forms, a few topics, recency words but not `current`/`now`; companies found in the text: aliases (Google, Facebook…), a unique first word of a name, word-like tickers such as `IT`, `ON`, `CF` only as `$IT`, one-word names only capitalized and not before another capitalized word, common-word names not at sentence start; a name beats a conflicting ticker), no translation.
2. Companies -> `cik` from the directory (`companies.py`): ticker, then normalized name (legal suffixes dropped: `AMAZON.COM, INC.` -> `amazon`), then a unique whole-word prefix of a known name (`Meta` -> `Meta Platforms`; never the reverse: `Apple Hospitality REIT` is not Apple). When every named company is missing from a corpus, it is not searched (another company's passages would answer the wrong question).
3. Hybrid search per corpus, one per company when several are compared (`search.py`): dense + BM25 prefetch 100 each, RRF, 50 candidates. Hard filters: `cik`, form, period. A period matches 10-K/10-Q by `fiscal_year`/`fiscal_period` (fiscal basis; Q4 -> `FY`) or by `period_end_date` (calendar basis: year Y = fiscal year ending 15 Jun Y – 14 Jun Y+1; a quarter = period end within ±45 days of the calendar quarter end); a year without a quarter reads the 10-K (`FY`) only, or, for a company with no 10-K for it yet (year in progress), that year's 10-Qs. 8-Ks match by `filing_date` from 47 days before the period end (read from the company's own 10-K/10-Q; a year in progress: its first to latest 10-Q end) to 100 days after; when forms has 8-K or topic `8k_event`, the whole period instead (to 120 days after a year's end, for shareholder letters; a calendar period from its first day); without a known end, a fallback window from the year; a filing month the user names (`filed_months`, `YYYY-MM`) admits any filing of that month plus 7 days besides the periods; a period without a year: 8-Ks around each end of that period in the company's filings (every 8-K when no company). `wants_latest` without a period: with a form (or topic `ex99`), the newest filing of it per company; otherwise filed within 400 days before the company's latest filing. Topics only boost (the same prefetches again restricted to them, fused together). Fewer than 8 candidates relax period/recency, then form; never `cik`. Candidates per search: max(50 // searches, top_k).
4. Same company and text (prefix excluded, case and whitespace folded) -> one candidate with the group's best score: the newest filing's copy when no year is asked; the collapsed chunk IDs stay in the ranking (`duplicate_chunk_ids`) for Recall@k.
5. Rerank all candidates (`rerank.default`). Qwen3-Reranker is a yes/no classifier that needs its chat template around query and documents: the profile sets `prompt_format = "qwen3"` and an SEC `instruction` (the format lives in the rerank profile), and `src/llm` applies them (without the template scores barely separate: 0.32 relevant vs 0.26 unrelated; with it 0.995 vs 0.0006). A failed reranker (error or an index out of range) is skipped for 120 s (fused order); candidates a `top_n` reranker leaves out rank below every scored one.
6. Scores scaled to [0, 1] plus 0.05 (0.25 when `wants_latest`) × a time bonus: without a year, filing recency; with a year whose filter was relaxed, closeness to that year; none when the year filter held.
7. Top k = 8, or max(8, 2 per company) in comparisons (each company, else each asked year, first gets `k // n`; an 8-K counts for the asked year whose 8-K window holds it, a calendar plan uses the period end's calendar year), expanded within 6,000 tokens (up to 2× when k grows) of chunk `token_count` (`expand.py`): all parts of a split table or paragraph (consecutive `chunk_ordinal`s), else ±1 neighbour in the same section, or a whole 8-K item of at most 4 chunks; selected chunks first, then context nearest first, round by round. Each side of a selected chunk stops at its first chunk that does not fit (a farther one would not touch the passage). Touching chunks of a section merge into one passage (a chunk whose prefix differs starts with `[prefix tail]`). More compared companies than slots: the best-ranked shares win.
- A `Retriever` resolves aliases, directories and search settings once: build a new one after an alias switch.
- Output (`RetrievalResult`): passages (text, prefix, company, form, period, section, `sec_url`, chunk IDs, selected chunk IDs, rank, score), the full candidate ranking (for Recall@k), resolved and missing companies, filters, notes (fallbacks, relaxations, collapsed duplicates), timings.
- Smoke set `scripts/rag/smoke_questions.txt` (22 questions, Vietnamese and English, the 5 local companies); `search.py --output` is rewritten after each question. On `data/` (2026-11-17; Groq gpt-oss-120b, Cloudflare embeddings, Qwen3-Reranker-0.6B on a Colab T4): median 6.7 s per question (query model 2.5 s, embedding 1.0 s, Qdrant 0.03 s, rerank 2.8 s for 50 candidates, expansion 0.01 s), ~5.8k context tokens.
